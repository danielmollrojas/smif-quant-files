STEP I — UNDERSTAND WHAT "KERNEL" MEANS

The notebook file itself does not contain its own Python installation.

The kernel is the Python process that ACTUALLY executes the notebook.

The kernel determines:

    - which Python version is used
    - which packages are available
    - which environment runs the code

That is why a notebook can work under Python (smif-quant) and fail under another
environment even when both say "Python 3.14".

That is NORMAL.

WHAT IS base/root?
------------------
When Anaconda is installed, it includes a default environment commonly called
"base" or "root." Think of base/root as Anaconda's main home environment.

It is better not to turn that main environment into a storage place for every
package used by every class or project.

Instead, this division uses a separate environment called:

    smif-quant

Think of smif-quant as its own self-contained workspace. It has its own Python
version and its own installed packages. In practical terms, it "lives in its own
place" so division work does not get mixed together with unrelated Python projects.

WHY ARE WE DOING THIS?
----------------------
1. Everyone in the group uses the same Python version: Python 3.14.
2. Everyone uses the same division environment: smif-quant.
3. Packages for another project do not get mixed into division work.
4. Updating or changing packages in a DIFFERENT environment does not change
   smif-quant.
5. Problems or package changes in base/root are less likely to affect this division.
6. The notebook is much easier to reproduce on different members' computers.

IMPORTANT:
The environment is isolated, but it is not permanently frozen. If you deliberately
update packages INSIDE smif-quant, you are changing smif-quant. For that reason,
use the repository's environment.yml file as the division setup recipe and avoid
unnecessary package upgrades.

Whenever you open the notebook, confirm that the selected kernel is:

    Python (smif-quant)

The notebook file itself is not permanently tied to one Python installation.
The kernel you select determines which Python version and packages actually run it.

TESTED DIVISION SETUP
---------------------

    Conda environment: smif-quant
    Python: 3.14
    Kernel: Python (smif-quant)

The exact environment path on your computer will be different from someone else's.

PART 1 — WHAT EACH TOOL IS ACTUALLY DOING
================================================

GitHub
------
GitHub is primarily where the workshop files are STORED and distributed.

For this workshop, think of GitHub like a public project folder with version
history.

GitHub can DISPLAY a .ipynb Jupyter Notebook in your browser, but a normal GitHub
repository does NOT execute the notebook code for you.

In other words:

    GitHub = where you get the files
    Anaconda = how you manage the Python environment
    JupyterLab / VS Code = where you actually run the code

There are cloud-development products such as GitHub Codespaces, and notebooks can
also be adapted for platforms such as Google Colab, but that is NOT the recommended
beginner workflow for this project.

The recommended beginner workflow is LOCAL:

    GitHub -> Download the project -> Anaconda/Conda -> smif-quant -> JupyterLab or VS Code -> Run notebook


Anaconda
--------
Anaconda is a Python distribution and environment-management system.

It helps you avoid the common problem of having several different Python
installations and not knowing which one is running your notebook.

Anaconda Navigator is the graphical interface.

For this workshop, Anaconda/Conda is used to create and manage one dedicated
environment named smif-quant. Do not run the division from base/root.


Jupyter Notebook / JupyterLab
-----------------------------
A .ipynb file is a Jupyter Notebook.

A notebook contains separate "cells." Some cells contain text and explanations.
Other cells contain Python code.

You normally execute code cells one at a time from top to bottom.

JupyterLab is the simplest interface for absolute beginners because the files are
Jupyter notebooks. VS Code is also fully supported as long as the selected notebook
kernel is Python (smif-quant).


VS Code
-------
VS Code is an editor that can also run Jupyter notebooks.

VS Code is optional for beginners, but it is fully supported for division work.

If this is your first time working with notebooks, JupyterLab is usually simpler.
If you prefer VS Code, use it — just select the Python (smif-quant) kernel.


CSV files
---------
A .csv file is a plain-text data file organized in rows and columns.

The notebooks in this project read CSV files directly.

The notebook code expects several CSV files to have specific names and to be
available from the notebook's working directory.

For this first upload, students should treat the downloaded GitHub repository as
one project folder. The notebook and the required CSV files should remain together
at the same relative level unless the repository is intentionally reorganized later.

PART 7 — WHAT "RELATIVE PATH" MEANS
================================================

This is one of the most important concepts for this project.

The notebook contains code such as:

    pd.read_csv('Amazon.csv')

Python is NOT being told:

    "Go to Daniel's Desktop and find Amazon.csv."

It is being told:

    "Look for a file named Amazon.csv relative to the current working location."

That makes the project portable.

---------------------

An absolute path would look like:

    C:\Users\John\Desktop\smif-quant-files\Amazon.csv

    pd.read_csv('Amazon.csv')

location and Amazon.csv is there.

PART 8 — HOW TO CHECK YOUR WORKING DIRECTORY
================================================

If you ever get a file-not-found error, create a temporary notebook cell and run:

    import os
    print(os.getcwd())

This tells you where Python currently believes it is working.

Then run:

    print(os.listdir())

This shows the files Python can currently see in that directory.

If you expect to see:

    Amazon.csv

but Amazon.csv is not listed, you have found the problem.


GOOD DIAGNOSTIC CELL
--------------------

    import os

    print("Current folder:")
    print(os.getcwd())

    print("\nFiles in this folder:")
    print(os.listdir())

This small check solves a very large percentage of beginner path problems.

================================================
PART 14 — RESTARTING THE KERNEL
================================================

A Jupyter "kernel" is the Python process running the notebook.

It remembers variables created during the current session.

Example:

You run:

    x = 10

The kernel remembers x.

If you close/restart the kernel, that memory disappears until you rerun the cell.


WHY "RESTART KERNEL AND RUN ALL" IS IMPORTANT
---------------------------------------------

During experimentation, you may accidentally create hidden state.

For example:

1. You run Cell 20.
2. You change Cell 5.
3. You rerun only Cell 20.
4. The notebook appears to work because old variables are still stored in memory.

A clean test is:

    Restart Kernel
    Run All Cells

If the notebook works from a completely fresh kernel, the notebook is much more
likely to be reproducible for everyone else.

PART 20 — COMMON ERRORS AND WHAT THEY USUALLY MEAN
================================================

ERROR:
    FileNotFoundError: [Errno 2] No such file or directory: 'Amazon.csv'

MOST LIKELY CAUSE:
    Python is working from a folder where Amazon.csv is not available, or the file
    was renamed/moved.

CHECK:

    import os
    print(os.getcwd())
    print(os.listdir())

Then verify that Amazon.csv appears in the list.


------------------------------------------------

ERROR:
    ModuleNotFoundError: No module named 'yfinance'

MOST LIKELY CAUSE:
    yfinance is not installed in the environment used by the notebook, OR the
    notebook is using the wrong kernel.

CHECK:
    Which kernel is selected?

First confirm that smif-quant is activated:

    conda activate smif-quant

Then confirm the notebook kernel is:

    Python (smif-quant)

If yfinance is still missing, compare your environment with the repository's
current environment.yml before installing anything manually.




------------------------------------------------

ERROR:
    NameError: name 'something' is not defined

MOST LIKELY CAUSE:
    A previous cell that creates "something" was not run.

FIX:
    Start at the top and run cells in order.

A clean solution is often:

    Restart Kernel -> Run All


------------------------------------------------

ERROR:
    PermissionError

POSSIBLE CAUSE:
    A CSV file may be open in another program, such as Excel, while Python is
    attempting to overwrite it.

FIX:
    Close the file in Excel and rerun the cell.


------------------------------------------------

ERROR:
    Kernel appears to use the wrong packages
    OR you receive ModuleNotFoundError even though setup was completed.

CAUSE:
    The notebook may be running a different Python interpreter from the one where
    the division packages are installed.

FIX:
    Select the "Python (smif-quant)" kernel.

    In VS Code, do not choose:
        base
        a global Python 3.14.x interpreter
        another environment such as quant

    The exact local path to smif-quant differs by computer. That is normal.

If necessary:

    conda activate smif-quant
    python -m ipykernel install --user --name smif-quant --display-name "Python (smif-quant)"


------------------------------------------------

ERROR:
    Yahoo Finance / yfinance request fails

POSSIBLE CAUSES:
    No internet connection.
    Temporary external data-source problem.
    Package compatibility/version issue.
    The external provider changed behavior.

FIRST:
    Confirm that your internet connection works.

SECOND:
    Confirm that yfinance is installed in smif-quant and that Python (smif-quant) is the active kernel.

Do not start moving local CSV files around; a web-data retrieval error is not the
same thing as a local file-path error.
